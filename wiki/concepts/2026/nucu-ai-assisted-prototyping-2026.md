# NUCU AI-Assisted App Prototyping — 2026

The archived April 7 and April 14, 2026 NUCU classes teach students to turn a clear user need into a small digital prototype. **Claude Code**, **Glide** and **Lovable** illustrate different amounts of platform abstraction and code control. A quick prototype helps explore a venture; speed alone does not validate demand, data, privacy or safety.

## Choose the level of control

**Glide** turns sample spreadsheet rows into an app. The exercise/sleep demo uses dates, workout names, sets and repetitions; a **Pexels** image column adds pictures, and a **Gemini** column makes unvalidated calorie estimates. Its visible layers are data, layout and workflow/logic. The platform manages much of the implementation, but students question backend control and UI flexibility.

**Lovable** is used to describe desired outcomes and generate a more bespoke app. The lecturer contrasts conversational iteration with delegating more work in agent mode. A plan step can refine requirements first. **React**, **Tailwind**, database storage and authentication are parts of the illustrated architecture, not evidence that a generated app is production-ready.

**Claude Code** edits actual files. April 7's website demo changes **“Apply now” to “Applications closed”**, then follows **local files → GitHub → Vercel build → refreshed page**. **Railway** is described as PaaS for supporting services. The class also shows a driving-hours micro-app and a prospective senior tech-support website; personal records are not needed to learn their design pattern.

## Work from broad to specific

1. Identify the user and **ICP, ideal customer profile**, and the problem worth solving.
2. Sketch a journey or wireframe with paper, Google Stitch, Figma, Canva or another tool.
3. State broad requirements, using sample data or a pitch deck to clarify the problem and users.
4. Generate a first version, inspect it and refine components.
5. Polish the visual details after the core behavior makes sense.

The instructor warns that automating a bad idea quickly still yields a bad idea. A class exercise compares a simple outcome prompt with a longer prompt generated by another LLM. Delegating tests is not evidence that tests were adequate; the recorded demos do not establish secure authentication or accurate numerical models.

## Two April 14 demonstrations

The Lovable prototype is a workout/sleep **PWA** with an anime-inspired brief. It chooses **deep purple, neon cyan and sunset orange**, glass-like cards, and the name **Sleep Sanctum**. CSS handles visual presentation; UI appearance does not prove backend functionality. The quoted minute-scale build timelines are ambitions rather than guarantees.

**Blake's Japan demographic map** reportedly uses **2020 census** data, age groups including **65+**, and a simulator showing years such as **2050**. He uses Claude to draft a prompt, Claude Code in VS Code to implement it, then adds functionality after seeing the first map. No dataset or projection method is supplied, so the results are not verified demographic predictions. The human reviewer approved publication of his name and unpublished prototype on 2026-09-30; this does not validate the projections.

The April 7 story of an unnamed **$1.8 billion healthcare company** is disputed during class; neither valuation nor misconduct allegations are verified. Keep the lesson about low-cost prototyping separate from claims of guaranteed startup success. See [[2026-04-07-nucu-session-12]] and [[2026-04-14-nucu-session-13]].
